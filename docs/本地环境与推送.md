## 1 · 网络：访问 GitHub **必须走本地代理**

| 事实 | 值 |
|---|---|
| 直连 `github.com` | ❌ 不通/极慢（`curl` 超时、`git fetch` 报 `Operation too slow`） |
| `api.github.com`（直连） | ⚠️ 时通时断 |
| **可用通道** | ✅ **本地代理 `http://127.0.0.1:7890`**（HTTP 与 SOCKS5 都可用；`7891` 备用） |
| 代理进程 | `iKuuuVPNC`（监听 `*:7891`、`127.0.0.1:7890`） |

**所有 git 远端命令都带上代理**（不要改全局配置，免得代理关掉后反而卡住）：

```bash
P=http://127.0.0.1:7890
git -c http.proxy=$P fetch origin --prune
git -c http.proxy=$P push origin <branch>
git -c http.proxy=$P ls-remote --heads origin
```

## 2 · GitHub 凭据：`gh` 已安装并接管 git，**但令牌会失效**

| 事实 | 值 |
|---|---|
| `gh` 可执行 | **`/Users/liuchun/.local/bin/gh`**（⚠️ **不在默认 PATH**，要用绝对路径或加进 PATH） |
| `gh` 配置 | `~/.config/gh/config.yml`（`git_protocol: https`）、`~/.config/gh/hosts.yml`（账号 `liuchun878`，active） |
| git 凭据助手 | `~/.gitconfig` 里 `credential.https://github.com.helper = !/Users/liuchun/.local/bin/gh auth git-credential` → **git 不需要 PAT，走 gh** |
| 本次实测 | ❌ `gh auth status` → *The token in default is **invalid***；`gh api user` → `Requires authentication` |

**令牌失效时的修法（一条命令，交互式）**：

```bash
# 建议同时带代理，避免 gh 连不上 GitHub
HTTPS_PROXY=http://127.0.0.1:7890 /Users/liuchun/.local/bin/gh auth login -h github.com
# 或：把新令牌直接喂进去
# /Users/liuchun/.local/bin/gh auth login -h github.com --with-token < /path/to/token
```

登录成功后**直接用 git 推即可**（无需 PAT、无需再配 helper）：

```bash
cd "<仓库>"
git -c http.proxy=http://127.0.0.1:7890 push origin feat/s-click-seat
git -c http.proxy=http://127.0.0.1:7890 push origin main
```

> 备选（不装 gh 的机器）：把 PAT 放进 `.tools/github-token`（已 gitignore），用一次性凭据助手：
> `git -c http.proxy=$P -c credential.helper='!f(){ echo username=<用户名>; echo password=$(cat .tools/github-token); }; f' push origin <branch>`

### 2.1 · ✅ 现状：**全局**凭据已就位（2026-10-04 14:16 实测）

`~/.config/gh/hosts.yml` 里现在有令牌（`--insecure-storage`，权限 `600`），
**全局生效**：任何目录、任何项目、任何 agent（含工作区沙箱内的 shell）都能直接
`git push`，**不需要** `GH_CONFIG_DIR`，也**不需要** PAT。

```bash
# 自检三条（都不带 GH_CONFIG_DIR）
/Users/liuchun/.local/bin/gh auth status                                  # → ✓ Logged in ... hosts.yml
printf 'protocol=https\nhost=github.com\n\n' | /Users/liuchun/.local/bin/gh auth git-credential get
git -c http.proxy=http://127.0.0.1:7890 push --dry-run origin main        # → Everything up-to-date
```

**为什么不用 keychain**：`gh` 默认把令牌写进 macOS keychain，但**沙箱内的 shell 读不到 keychain**
（`security` 报 `A Module Directory Service error`）→ `gh auth status` 显示 *token is invalid*、
helper 取不到密码 → `git push` 报 `could not read Username`。**只有落到文件才对所有 agent 生效。**

**重新登录（两种）**：

```bash
# ① 令牌还有效，只是要改存储方式 —— 需要提权（要写 ~/.config/）
T=$(/Users/liuchun/.local/bin/gh auth token)
printf '%s\n' "$T" | /Users/liuchun/.local/bin/gh auth login -h github.com --with-token --insecure-storage
/Users/liuchun/.local/bin/gh auth setup-git

# ② 令牌真的失效了 —— 交互式设备码流程，**必须带代理**
printf '\n' | HTTPS_PROXY=http://127.0.0.1:7890 HTTP_PROXY=http://127.0.0.1:7890 \
  /Users/liuchun/.local/bin/gh auth login -h github.com -p https -w
#   → 打印一次性验证码，浏览器打开 https://github.com/login/device 输入
```

| 坑 | 现象 | 原因 / 解法 |
|---|---|---|
| 直连跑 `gh auth login -w` | `failed to authenticate via web browser: Post ".../login/device/code": TLS handshake timeout` | 设备码接口**直连不通** → 必须带 `HTTPS_PROXY` |
| 沙箱内 `gh auth login` | `open ~/.config/gh/hosts.yml: operation not permitted` | 沙箱只许写工作区 → 本次登录要**提权**（`danger-full-access`） |
| 只信 keychain | 提权 shell 里 `gh auth status` 正常，普通 shell 里 invalid | 沙箱读不到 keychain → 用 `--insecure-storage` 落文件 |
| 降级方案（不能提权时） | —— | `export GH_CONFIG_DIR=$PWD/.tools/ghconfig`（沙箱内可写），但**只对当前项目当前会话有效**，属降级，不推荐 |

> 只读操作（`git fetch` / `ls-remote`）走代理或不走通常都行；
> **写操作（push）带代理最稳**：实测直连 `git fetch` 会挂住不返回。

## 2.2 · 通道选择：不要在一条通道上死等

本机去 GitHub 有**多条通道**，快慢与死活会变（同一个 `127.0.0.1:7890` 一会儿通一会儿关）。所以：

| 做法 | 命令 |
|---|---|
| 1 秒探端口，别等 | `(exec 3<>/dev/tcp/127.0.0.1/7890) 2>/dev/null && echo OPEN \|\| echo closed` |
| 探接口（带超时） | `curl -s -m 8 -o /dev/null -w '%{http_code} %{time_total}\n' https://api.github.com/` |
| **让 git 自己快失败** | `git -c http.lowSpeedLimit=1000 -c http.lowSpeedTime=10 <cmd>` —— 慢于 1 KB/s 持续 10 s 就断，不干等 |
| 换通道重试 | 直连挂住 → 立刻换 `-c http.proxy=http://127.0.0.1:7890`（反之亦然） |

**判据**：同一条通道**不要连续等超过 30 秒**；`curl` 已 200 但 `git fetch` 不动，就直接换代理通道。

## 6 · `main` 被推进了怎么办（**不要硬 merge**）

这个仓库的 `main` 是**多人在写**（`liuchun878` / `YuMi-06` / `IXaglis`），任何一次推送之前都要先看远端。

| 情形 | 做法 |
|---|---|
| 本地**只是领先** `origin/main`（`0 落后`，快进） | ✅ 直接 `git push origin main` |
| 本地**落后或分叉**，且出现冲突 | ❌ **不要**把远端 merge 进 `main` 硬推 —— 先把本地提交推到**分支**：`git push -u origin feat/<主题>`，再开 PR，PR 里说明冲突点与取舍，让 owner 决定 |
| 提交落在错误分支（如切到 `0000000` 上） | 用 `git cherry-pick` 挪回 `feat/*`，`main` 保持只走"快进 + 里程碑 tag" |

```bash
# 推之前 3 秒判据
git -c http.proxy=$P fetch origin --prune
git rev-list --left-right --count origin/main...main   # 左=落后  右=领先
#   0  N  → 领先，可直接推 main
#   N  0  → 落后，先 pull --ff-only
#   N  M  → 分叉，走分支 + PR（别硬 merge）
```

> 本轮（v1.20）实测就是 `0 落后 / 1 领先` → 直接快进推 `main` 并打 tag `v1.20-保卫老人`。
