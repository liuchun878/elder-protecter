## 3. D1 演示 Demo 的形式约束

### 3.1 硬约束（违反即为不合格）

| 约束 | 值 | 检验方式 |
|---|---|---|
| 文件数 | **1**（单文件 HTML） | 目录里只有一个 `index.html` |
| 外部依赖 | **0** | `grep` 无 `<link`、无 `<img src>`、无 `@font-face`、无 `fetch(`、无 `getUserMedia` |
| 体积 | ≤300KB | 文件属性 |
| 离线可用 | 是 | DevTools Offline + `file://` 双击，两条都通过 |
| 摄像头 / 录音 | 不使用 | 同上 `grep` |
| 上传行为 | 无 | 同上 `grep` |

### 3.2 两个视图 + 演示控制台

| 视图 | 内容 | 可见性 |
|---|---|---|
| **老人端** | 到点整屏大字卡片 + 语音播报药名与片数 + **一个绿色大主按钮「我吃了」** + 次要按钮「晚点吃」（snooze 5 分钟）「跳过」+ **按下后 5 分钟内可撤销** + 今日记录列表 + **当日完成度进度条** | 默认视图 |
| **家属端** | **只读看板**：今日时间线、「**15 分钟未确认 → 再提醒一次；30 分钟仍无记录 → 升级**」的本地定时器与一条**模拟**通知、本周**记录率**、每条的「我打电话确认了」按钮 | 顶部角色切换 |
| **演示模式** | 「到点」「快进」两个按钮把人触发；**同时保留真实 `setTimeout` 路径**，演示时说明两者区别 | **默认折叠**（评委不该看到） |

**唯一可写入口**：一次性设置表单，**4 个字段**——自由文本药名 + 剂量字符串 + 每日次数 +
时刻列表；内置 5–10 条示例数据。**不做** NMPA 对接、处方对接、真实 OCR、编辑/删除/
多规则/多档案 CRUD；看板本身只读。

### 3.3 适老化硬指标

| 指标 | 达标值 | 出处 |
|---|---|---|
| 正文字号 | ≥18dp/pt（本 Demo 取 ≥20px） | 工信厅信管函〔2021〕67 号 |
| 标题字号 | ≥30px | 同上 |
| 对比度 | ≥4.5:1；>18dp/pt 处 ≥3:1；另提供高对比模式 | 同上 |
| 首页主要组件点击焦点 | ≥60×60dp/pt，间距 ≥16px | 同上 |
| 字距 | ≥1.3 倍 | 同上 |
| 手势 | 不使用 ≥3 指手势 | 同上 |
| 验证码 | 不使用非文本验证码 | 同上 |
| 广告 / 诱导按键 | 完全没有 | 同上（适老版严禁） |
| 嵌套弹窗 | 禁止 | 先例：智康 Agent README |
| 无障碍 | ARIA label、可预测焦点顺序、`prefers-reduced-motion` | 同上 |

**第一验收项是「入口可见性」**，不是界面美观：老人「不知道有长辈模式，也不知道入口
在哪」。因此老人端页面**本身就是那块固定屏**，没有入口要找。

量测方法：DevTools 取 computedStyle 逐条核对，结论记入 `docs/usability-log.md`。

## 4. 状态语义与禁用词（**逐字照抄第 9 问交付稿，不得改写**）

### 4.1 四状态机

| 状态键（代码内） | 屏幕文案 | 含义 | 谁产生 |
|---|---|---|---|
| `reminded` | **已提醒** | 到点已提醒，尚无记录 | 系统 |
| `notRecorded` | **未记录** | 30 分钟内没有任何记录 | 系统 |
| `recordedBySelf` | **已记录（本人按键）** | 自述（self-report） | 老人 |
| `confirmedByHuman` | **家属已确认（人证）** | 人证（human witness） | 家属 |

辅助键（非四状态）：`scheduled`（屏幕「待服药」）、`skipped`（屏幕「已跳过」，须记原因）。

**动作集**：主按钮「我吃了」→ `recordedBySelf`；「晚点吃」→ 重置 `dueAt` 回 `reminded`；
「跳过」→ `skipped`；**5 分钟内可撤销**；家属「我打电话确认了」→ `confirmedByHuman`。

### 4.2 禁用词表（硬约束）

- 屏幕上**允许**：`已提醒` / `未记录` / `已记录（本人按键）` / `家属已确认（人证）`
- 屏幕上**禁止**：`已服药` / `已确认服下` / `按时吃了` / `依从率达标`
- 家属端指标标题**必须写 `记录率`**，**不能写「服药率」**

**为什么这是规则而不是谨慎**：厂商一手开发者文档里智能药盒只上报开盖/取用/补充三类
事件，没有任何吞咽事件；连做药盒起家的 Hero Health，公开 API 事件枚举里连「取药」都
没有。唯一方向接近「服下」的是视频观察（vDOT），其确认来自人看画面，而 PLoS NTD 2024
的 4 项 RCT／1044 例**只报依从性非劣，未报假阳性/假阴性率**。中国本地试验自述：
「目前没有测量依从性的金标准，因为没有任何测量能直接确认药物摄入」。

**合规侧收益**：越不宣称「确认服药/剂量控制」，越接近已被界定为「不作为医疗器械管理」
的先例（「幼儿喂药器」界定理由即「声称产品无剂量控制功能」；国食药监械〔2008〕587 号
「医用配药机…不作为医疗器械管理」）。

## 5. 记录率口径（家属端唯一指标）

```
记录率 = （已记录（本人按键）条数 + 家属已确认（人证）条数） ÷ 应服条数 × 100%
```

- 标题写 **`记录率`**，不写「服药率」「依从率」
- 分子**不含**「未记录」「已跳过」
- 「已跳过」需记原因，原因单列，不计入分子
- 口径一旦定下，Day 2 测试期间不得更改

## 6. 验收：什么叫「做完了」

### 6.1 演示维度

- [ ] 60 秒内走完第 9 问交付稿 §一.2 的 **7 步演示线**（含一次「未记录」升级）
- [ ] 断网 + `file://` 双击两条路径都通过
- [ ] 找 1 位没参与项目的人看 60 秒：能答出「这东西是干嘛的」；「你会用吗」不需要想超过 3 秒
- [ ] 排练 ≥3 遍并计时，最长 ≤60 秒

### 6.2 证据维度

- [ ] ≥5 个可引用的实测数字 + 3 条局限（诚实页）
- [ ] 任务完成率**两种口径**都报：按任务百分比 + 按人四档（**不得加权平均**）
- [ ] ≥3 句老人原话可直接上幻灯片
- [ ] SUS 计分器经已知样例验算
- [ ] 如实写明 N=7–8、无统计检验、SUS 只作方向性指标

### 6.3 过程维度

- [ ] 7 个 tag + 7 个 Release，每个含产出与验收结论
- [ ] `docs/usability-log.md` 中每个卡点都有对应 commit 或「不修 + 理由」
- [ ] `git status` 干净，仓库内无构造性垃圾

### 6.4 诚实维度（**决定作品可信度**）

- [ ] `grep` 全文确认屏幕上无 `已服药` / `已确认服下` / `按时吃了` / `依从率达标`
- [ ] 家属端指标标题为 `记录率`
- [ ] README「已知局限」写明：**页面关闭后无法到点提醒**
- [ ] 演示第 4 段讲明最大风险「到点这一格纯网页做不到系统级推送」
- [ ] 「到点」是 Wizard 人工触发这件事，演示时**明说**
