## 二、决策清单

### D1 · 把报告的三天排期压成两天 🧑🔧

- **备选**：(a) 延长到 3–4 天；(b) 仍是两天；(c) 不锁天数只排依赖
- **决定**：仍两天，把 Day 3 的适老化打磨与排练压进 Day 2 下午
- **代价**：报告原排期没有缓冲日。**必须配降级阶梯**，否则一定压线
- **影响**：→ D10 人时预算

### D2 · 呈现形态 = 3D 居家仿真场景 🧑

- **备选**：(a) 软件内置 2D 居家场景动画；(b) 2D 场景 + 真人扮演王阿姨；(c) 3D（Three.js）；(d) 其他
- **决定**：(c) 3D
- **过程留痕**：**最初选的是「单文件原生 HTML+JS」**，第 2 轮讨论改为 3D。这次改动的连锁后果由 D3、D4 承担
- **代价与对策**：3D 在两天内是高风险项 → 用 **D8（仿真层与功能层解耦）** 兜住：3D 挂了就降级 2D，**功能一条不少**

### D3 · Three.js 必须本地 vendored，且必须用静态服务器 🔧

- **实测事实**（不是推测）：`three@0.186.1` 的 `build/three.min.js` 返回 **404 —— UMD 构建已移除**，只剩 ES module；`three.module.js`（662,772 B）内部 `import ... from './three.core.js'`（1,458,113 B），**共约 2.12 MB 两个文件**
- **推论**：ES module 在 `file://` 下被 CORS 拦截 → **双击 HTML 打不开，必须先起静态服务器**（`python3 -m http.server 8000`）
- **否决的备选**：走 CDN —— 直接违反「断网必须可用」红线（📊 报告第 09 章）

### D4 · 不做实体机器人 📊

- **依据**：TowerView 永久关闭、Pillo 被收购后产品线终止、**Samsung Ballie 因导航/续航 2–3 小时/隐私问题无限期搁置**（报告第 03 章）
- **推论**：移动底盘 + 导航 + 视觉确认，是三星都判定无法商业化的工程量；两天做硬件等于必败

### D5 · 卖点从「会提醒」改成「送到手边 + 记下吃了没」 📊

- **依据**：Cochrane 汇总 182 项 RCT 结论是提醒类干预「大多数复杂、效果不佳」且拒绝做 Meta 分析；REMIND（n=53,480）三种廉价提醒装置与对照组**无差异**；而效应最大的特征是**物理分装（OR 2.453）与数据共享（OR 2.404）**——即「送达」与「确认记录」（报告摘要 1、第 02 章）
- **影响**：整个原型的中心是**确认 + 记录**，不是提醒次数

### D6 · 分工按产出切：R 机器人 / S 场景 / H 人 🧑

- **备选**：(a) 前后端/算法分层切；(b) 按报告第 08 章的 A/B/C 职责切；(c) 按演示角色——机器人 / 场景 / 人
- **决定**：(c)。三人各对应演示场景里的一个角色，"人"是可见主体，正好支撑答辩时"最大风险是老人觉得被监控"的论述
- **已知代价**：报告第 08 章明确警告**不能按技术层切**，因为会导致「没人对整体闭环负责」「没人对 60 秒陈述负责」。所以 (c) 必须配 **D7** 才成立

### D7 · 闭环按「环节」落到三条线，不留无主环节 🔧

- **背景**：这是本轮**最重要的修正**。只分机器人/场景/人，闭环极易变成无主——机器人走完、场景画完、人摆完，没人写"药到底拿没拿、没拿怎么通知家属"
- **决定**：把闭环拆成 **11 个环节**，每个环节指定唯一主责（见 [plan/tasks.yaml](../plan/tasks.yaml) 的 `closed_loop_ownership`）：
  计划→H｜时间→S｜到点判定→H｜送达→R｜提示→R｜取药确认→H｜记录→H｜升级→H｜家属闭环→H｜装配门禁→S｜陈述→R
- **同时定的两条**：
  - **只保一件事时，保 H 线的闭环**（机器人可以是方块，房间可以是色块，闭环不能没有）
  - 陈述**主讲（R）不兼任演示操作（S）**，且主讲不承担关键路径的最后一块

### D8 · 仿真层与功能层解耦；业务状态机只由 H 写 🔧

- **两条规则**：(1) 依赖单向 `H ← R/S`，H 永不 import 表现层；(2) `machine.js` 只由 H 写，**R 的机器人行为必须是 state 的纯函数**
- **为什么**：(1) 让 3D 可整体降级为 2D 而功能不减——这是敢在两天内用 3D 的前提；(2) 两套状态机必然漂移，且会让人误以为"机器人线也在做闭环"

### D9 · 文件独占所有权 + 固定合并顺序 + 交叉验证 🔧

- **文件独占**：一个文件只有一条线能改 → 把并行冲突率压到接近零
- **合并顺序**：`H → R → S`（依赖单向，装配层最后）。**每个里程碑合并一次**
- **职责分开**：门禁执行 = S；契约变更发起 = H（避免自己验自己）
- **交叉验证环**：H 的产出由 R 验、R 的由 S 验、S 的由 H 验；**按验收脚本由非作者重放**
- **否决备选**：搭 CI —— 两天内成本大于收益；改用「每条 PR 自检清单 + 人工门禁」

### D10 · 人时超载不掩盖，用「最先砍」清单释放 🧑

- **真实数字**：WBS 明细 **≈69.5 人时**（按 S=1/M=2.5/L=4）vs 两天可用 **≈44 人时** → **约四分之一到三分之一的明细任务不会进这两天**
- **决定**：不假装能全做完。每个任务标 `cut_first`，在 Day 2 12:30 与 14:30 两个门禁按阶梯砍，**不靠加班**
- **留痕**：早期文档里写的「约 56 人时 / 超约 10%」是估算，已被这组实数取代

### D11 · 让 agent 能读到全部关键信息（实测加载机制） 🔧

- **实测事实**：读 DSH 的 `agent-instructions` 实现确认——候选文件名是 **`AGENTS.md` / `CLAUDE.md`**（本地叠加 `AGENTS.local.md` / `CLAUDE.local.md`），加载范围是**「项目根（以 `.git` 为标记）→ 当前工作目录」整条链**，越具体优先级越高；整链渲染总量受 `maxBytes` 限制（研究模式 65536 字节）
- **决定**：**根 `AGENTS.md` + 嵌套 `prototype/AGENTS.md`**，长内容一律放 `docs/` 引用而不内联（避免撑爆上限）；另配机器可读真相层 `plan/tasks.yaml` + `STATUS.md`
- **验证**：两份嵌套文件均已被 harness 自动加载生效（对话中可见其作为 workspace instructions 出现）
- **强制约定**：改状态必须同步更新 `tasks.yaml` 与 `STATUS.md`，否则下一个 agent 会读到过期信息

## 三、被否决或搁置的方案

| 方案 | 处置 | 原因 |
|---|---|---|
| 真人扮演王阿姨的现场情景剧 | **搁置（可选增强）** | 情绪传染强、答辩好看，但多出调度与预演成本，且依赖现场走位与人员 |
| Three.js 走 CDN | **否决** | 违反"断网必须可用"红线 |
| 引入外部 3D 模型资产（GLB/贴图） | **否决** | 建模、授权、体积三样都是两天内的风险；改用纯几何体拼装 |
| 单文件原型 | **否决** | 与 3D + 三人并行冲突；文件粒度不足以支撑"文件独占所有权" |
| 3D 场景里渲染文字 | **否决** | 报告第 06 章的对比度/字号硬数值只能在 HTML/CSS 里逐条核验；改为全部走 HTML 叠层 |
| 两套状态机（业务一套 + 机器人一套） | **否决** | 必然漂移；改为"机器人行为是 state 的纯函数" |
| 用语音识别做服药确认 | **否决** | 主流 ASR 在 75–85 岁中国老人上零样本字错率 **>50%**（Whisper-large-v3 = 57.74%），微调后仍 23.84%（报告第 06 章）；改为大按钮/实体确认 |
| 自动补服建议 | **否决（红线）** | NHS 各药口径互斥（氨氯地平"跳过"vs 华法林"想起来就补"），软件无法逐药穷举；且同类"药物计算软件"在中国属 **Ⅲ 类器械** |
| 自动呼叫急救 | **否决（红线）** | 真实世界可穿戴设备阳性预测值低至 **0.02**（84 次报警 83 次误报） |
| 向家属推依从性评分/排名 | **否决（红线）** | 会加剧过度监控与家庭冲突；照护者本就依赖未经验证的信息 |
| 搭 GitHub Actions CI | **搁置** | 两天内成本 > 收益；改用 PR 自检清单 + 人工门禁 |
| 把 27 个任务逐个建成 GitHub Issue | **搁置** | 两天内维护成本高；`plan/tasks.yaml` + Milestone 更快 |
| 把 token 内嵌进 `git remote` URL 以便推送 | **否决** | 会把密钥持久写进 `.git/config`；改用 `GIT_ASKPASS` 临时脚本 |
| 手工逐个建 Issue/Milestone 归类 | **搁置** | 见上 |

## 六、诚实反思：如果重来一次

1. **应该更早冻结契约**。契约是本轮最后才补的，但它其实应该是第一个产物——三个人并行的前提是接口先定，而不是先讨论呈现形态。
2. **天数一确定就该立刻算人时**。早期文档写"约 56 人时、超约 10%"是估算；实数（69.5 vs 44）是在排三线分工时才逼出来的。**先算再排，会少改一轮文档。**
3. **呈现形态与分工应该一起定**。形态变了（2D→3D），分工、技术栈、人时预算、文件结构全都跟着变，导致多轮返工。
4. **"agent 能读到"这件事该在第一天就做**。它是零成本的，却决定了每次新会话会不会重新踩同一个坑。
5. **调研报告里的红线一开始就该做成可勾选清单**，而不是散文——它每天都要被用一次。
