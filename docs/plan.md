## 3. 五格最小闭环（照抄第 9 问交付稿，不重写）

> 立项文档第 22 页的 ④ 五格原为**全空**，⑥ 分工与风险也是空的。第 9 问交付稿把这几格
> 填好了。**本计划不再另立一套口径**，以下为交付稿的结论摘要，逐字可抄内容见原文。

| 格 | 内容 |
|---|---|
| **开始** | 老人不需要带任何设备、也不需要自己找入口：家里人一次性把「几点、吃哪种药、几片」录进家属端，并把老人端那台设备（家里已有的平板/手机，或电脑投到电视上）点亮、固定在长辈版，放在他每天坐着的位置。老人每天只是走到那块屏前，或者听到它开口说话。 |
| **输入** | 老人全程只提供两个输入：按一下最大的那个绿色按钮「我吃了」，或在实在看不清时说一句「晚点吃」。药名、剂量、时间全部由家属在开始时一次性录入，老人一次都不用打字。 |
| **处理** | 到点它做三件事：整屏大字卡片 + 语音播报药名与片数；如果 30 分钟内没有任何记录，就把这一条标成「未记录」并推给家属；如果家属打电话确认了，就把状态改成「家属已确认」。它只记时间戳和「谁确认的」，不做任何医学判断，也不判断药物有没有被吞下去。 |
| **结果** | 老人看到：一屏大字、一条语音、按完按钮变成绿色「已记录」。家属看到：一条时间线（7:02 已记录／7:00 未记录／7:31 家属已确认），和本周一个数——**记录率**。 |
| **继续** | 老人第二天照常。家属把每一条「未记录」当成一次动作：先打电话，打不通再上门；连续几天都未记录，家属端提示的是「联系家庭医生」——由人做决定，产品不下判断。 |

**五格的行为学框架**（被追问时用）：COM-B（Michie 等 2011, *Implementation Science* 6:42）。
问题不在 capability，而在 **physical opportunity（没有线索在正确时间点推动）+ social
opportunity（没人知道）**。对应干预功能正是 **Environmental restructuring**（「在屏幕上
给出提示」）与 **Enablement**。BCTTv1 编码：**7.1（到点提示）+ 2.3（本人按键记录）+
3.1（家属支持）+ 9.1（可信来源）+ 1.1（初始设定）**。

**为什么「继续」格只写升级与兜底、不写疗效承诺**：证据支持「提醒 + 记录」，**不支持**
「把数据给家属就能提高依从」——Kessler 2018（n=179）里「仅家属伙伴」43.2%（p=0.25，
不显著）而「仅告警」52.9%（p=0.002）；Reddy 2016（n=126）家属反馈与本人反馈在 4–6 个月
都回到不显著。所以家属这一格是**升级与兜底**，不是疗效通路。

## 4. 交付物形态规格

### 4.1 单文件技术约束

- **零外部资源**：无 CDN、无网络字体、无 `<link>`、无 `<img src>`、无 `fetch`。
  机器人/状态形象用**内联 SVG 自绘**。
- **语音**：只用 `speechSynthesis` 播报（不接付费 TTS），**不做语音识别输入**——
  通用 ASR 对 75+ 老人零样本近乎不可用（Whisper 全系列零样本 CER >50%，重度口音 80.95%）。
- **数据**：`localStorage`，键前缀 `t4.`，含 `schemaVersion`；隐私模式下自动降级内存态。
- **到点触发**：**演示时为人工触发的两个按钮**——「到点」与「快进 30 分钟」。
  不做 1×/60× 时钟倍速（第 9 问交付稿已明确「到点这一步是人工触发」，演示时必须明说）。
- **定时**：不用相对计时器累加；以 `dueAt` 绝对时间重算，在页面载入、`visibilitychange`、
  `setInterval` 三处触发。
- **无摄像头、无录音、无上传**：不调 `getUserMedia`；不向任何服务器发送数据。
- **体积上限**：≤300KB。
- **通知**：`Notification` API 仅作演示增强；拒绝则降级为页面内红点，且**在 UI 标注
  这是模拟通知**。

### 4.2 两个视图（同一文件内角色切换，不做多端同步的假承诺）

| 视图 | 内容 | 可见性 |
|---|---|---|
| **老人端** | 到点整屏大字卡片 + 语音播报药名与片数 + **一个绿色大主按钮「我吃了」**（次要按钮「晚点吃」「跳过」；按下后 5 分钟内可撤销）+ 今日记录列表 | 默认视图 |
| **家属端** | **只读看板**：今日时间线、「30 分钟未记录 → 升级」的本地定时器与一条模拟通知、本周**记录率**、每条的「我打电话确认了」按钮 | 顶部角色切换 |
| **演示控制台** | 「到点」「快进 30 分钟」、载入演示数据、重置 | **默认折叠**（评委不该看到） |

> **一处需要说明的取舍**：「五格·开始」要求家属一次性录入药名/剂量/时间，而三天范围
> 写的是「家属端**只读看板**」。两者并不矛盾——**只做一个一次性设置的录入表单**
> （首次建立计划用），不做编辑/删除/多规则/多档案的 CRUD 模块，看板本身只读。
> 这是本计划对该处张力的处理方式，不是原文原话。

### 4.3 适老化硬指标（逐条量测）

源自工信部信管〔2020〕200 号 + 工信厅信管函〔2021〕67 号《移动互联网应用（APP）
适老化通用设计规范》，见 `_research_用户界面可用性与数字鸿沟.md` 表 C3：

| 指标 | 达标值 |
|---|---|
| 正文字号 | ≥18dp/pt（本 Demo 取 ≥20px） |
| 标题字号 | ≥30px |
| 对比度 | ≥4.5:1（>18dp/pt 处 ≥3:1）；另提供高对比模式 |
| 首页主要组件点击焦点 | ≥60×60dp/pt，间距 ≥16px |
| 字距 | ≥1.3 倍 |
| 手势 | 不使用 ≥3 指手势 |
| 验证码 | 不使用非文本验证码 |
| 广告 / 诱导按键 | 完全没有 |
| 嵌套弹窗 | 禁止 |

## 5. 数据模型与状态机

### 5.1 状态（**四状态，名称不可改**）

第 9 问交付稿 §1.1 给出的唯一四状态机，本计划照用：

| 状态键（代码内） | 屏幕文案 | 含义 | 谁产生 |
|---|---|---|---|
| `reminded` | **已提醒** | 到点已提醒，尚无记录 | 系统 |
| `notRecorded` | **未记录** | 30 分钟内没有任何记录 | 系统 |
| `recordedBySelf` | **已记录（本人按键）** | 自述（self-report） | 老人 |
| `confirmedByHuman` | **家属已确认（人证）** | 人证（human witness） | 家属 |

外加两个非四状态的辅助键：`scheduled`（屏幕写「待服药」，未到点）与
`skipped`（屏幕写「已跳过」，老人或家属主动跳过，**须记原因**）。

**动作集**（照第 9 问交付稿 §一.2）：主按钮「我吃了」→ `recordedBySelf`；
次要「晚点吃」→ 重置 `dueAt` 回到 `reminded`；次要「跳过」→ `skipped`；
按下后 **5 分钟内可撤销**；家属点「我打电话确认了」→ `confirmedByHuman`。

### 5.2 禁用词表（**硬约束，违反即为不合格**）

屏幕上**允许**出现：`已提醒` / `未记录` / `已记录（本人按键）` / `家属已确认（人证）`

屏幕上**禁止**出现：`已服药` / `已确认服下` / `按时吃了` / `依从率达标`

家属端那一栏的标题**必须写 `记录率`**，**不能写「服药率」**。

一段可直接背下来的口播：

> 我们不知道药有没有被吞下去。我们只知道三件事：提醒有没有发出去、本人有没有按键、
> 家属有没有确认过。这三件事之外，我们什么都不说。

**依据**：厂商一手开发者文档里，智能药盒的可用事件只有 `pillbox_opened` /
`pillbox_refill_initiated` / `pillbox_refilled`，没有任何「吞咽」事件（Tenovi Docs）；
连做药盒起家的 Hero Health，公开 API 事件枚举里连「取药」都没有。唯一方向接近「服下」
的是视频观察（vDOT），其确认来自人看画面，且 PLoS NTD 2024 的 4 项 RCT／1044 例
**只报依从性非劣，未报假阳性/假阴性率**。中国本地试验自述：「目前没有测量依从性的
金标准，因为没有任何测量能直接确认药物摄入」。

**合规侧收益**：越不宣称「确认服药/剂量控制」，越接近已被界定为「不作为医疗器械管理」
的先例——2025 年第二次分类界定汇总第（四十）项「幼儿喂药器」（理由即「声称产品无剂量
控制功能」）、国食药监械〔2008〕587 号「医用配药机…不作为医疗器械管理」、NMPA
《采用机器人技术的医用电气设备分类界定指导原则（征求意见稿）》第三条（用于药品运输、
分拣、储存的机器人设备不作为医疗器械管理）。见 `合规准入与隐私_子问题研究记录.md` §1.2/§1.3。

### 5.3 localStorage 键（前缀 `t4.v1.`）

```
t4.v1.meta      { schemaVersion:1, seeded:bool, createdAt }
t4.v1.family    { familyId, elderName, createdAt }
t4.v1.meds[]    { id, name, dose, unit, note, active }
t4.v1.schedule  { times:["07:00"], medId, days:[0..6] }     ← 只做一次性设置，不做多规则 CRUD
t4.v1.doses[]   { id, medId, dueAt:ISO, state, closedAt }
t4.v1.events[]  { id, doseId, at:ISO, type, actor:"elder|family|system", payload }
t4.v1.settings  { escalationAfterMin:30, undoWindowMin:5, ttsEnabled, highContrast }
```

**记录率**（家属端唯一指标）= `已记录（本人按键）+ 家属已确认（人证）` 的条数 ÷ 应服条数。
口径写进 [deliverable.md](deliverable.md)。

### 5.4 升级链（两份团队文档的口径已合并）

| 触发 | 动作 | 降级 |
|---|---|---|
| `dueAt` | 老人端整屏大字卡片 + 语音播报「该吃 XX 药了」 | 无 TTS → 纯视觉 + 大字 |
| `dueAt + 15 min` 且无响应 | **再提醒一次** | 同上 |
| `dueAt + 30 min` 且仍无记录 | 状态改 `未记录`；家属端出现红点 + 一条**模拟**通知 | Notification 被拒 → 页面内红点 |
| 家属点「我打电话确认了」 | 状态改 `家属已确认（人证）` | — |
| 连续多日未记录 | 家属端提示「建议联系家庭医生」 | **由人做决定，产品不下判断** |

| 通道 | 现行依据 | 对三天 Demo 的含义 |

### 5.6 三天里最可能卡住的六件事（照支撑报告 §6.4，按可能性排序）

1. **到点触达**——纯前端页面关闭后不保证触发。后端替代各有硬约束：GitHub Actions
   `schedule` 最短间隔 5 分钟、高负载会延迟并可能丢弃、**公开仓库 60 天无活动后定时
   工作流被自动禁用**；Cloudflare Workers Free 每账户 5 个 Cron Trigger、每次调用
   **10 ms CPU**、Cron 按 UTC 执行且改动最长 15 分钟生效；腾讯云 SCF 免费额度**只限
   新用户前三个月**。
2. **微信通道**——一次授权一条；长期订阅准入未公开；三天只能体验版。
3. **药品数据结构化**——无开放 API，签约通道 15 个工作日。
4. **电话/短信外呼**——个人主体被云厂商明确关闭，需企业主体。
5. **非编码时间**——METR 唯一随机现场试验实测**慢 19%**；自报速度偏差 40 个百分点；
   编码约占周工作量 11%，而**环境搭建**是生产力/满意度回归里最强负预测因子。
   **任何「AI 让三天等于六天」的说法都没有实测支撑。**
6. **合规话术**——不要宣称剂量控制或「确认服下」；处理医疗健康信息需单独同意、事前
   PIA、记录至少保存三年（PIPL 第 28/29/30/55/56 条；《网络数据安全管理条例》
   国务院令 790 号，2025-01-01 施行）。

**免费依赖与备用通道**（第二天上午就能接上）：TTS 首选浏览器 `SpeechSynthesis`（零成本、
不必注册）；音频不够好再考虑讯飞（默认每日 500 次免费）。**必须纠正的假设：智谱
BigModel 的语音模型没有免费档**——GLM-TTS 2 元/万字符、GLM-ASR-2512 输入 16 元/百万
Tokens；免费的只是文本与视觉模型，不要把「GLM-4-Flash 免费」外推到语音。把通知送到
手机的免费通道：PushPlus（实名后微信渠道 200 次/天，**不需要企业主体**）、企业微信群
机器人 webhook（≤20 条/分钟）、Server酱（测试期免费）。

## 9. 测试与指标计划

- **人数**：5 位老人（3×70+、2×60–69）+ 2–3 位家属/照护者。定性找问题用 NN/g 的 5 人
  口径；要报 SUS 数字严格需 ≥20 人，**三天做不到，因此只报方向性指标并注明 N**。
- **对照锚点**（直接用于答辩）：
  - 15 种同类产品平均需 **12.7 个步骤**、**15.19 分钟**完成设置，完全无需协助完成全部
    步骤的仅 **55.3%**；自动配药机 MedReady 的 SUS 只有 **28.63**，显著低于 TimerCap
    **78.67**（Patel 2020，主报告 §2.4）
  - 同类家居改造研究：6 名 65+ 居家老人平均 SUS **71.7（SD 27.1）**，方差极大；
    6 名职业治疗师 SUS **91.7（SD 8.0）**；**老人任务准确率 60% vs 职业治疗师 93%**
  - SUS 判读：<70 不可接受 / >70 良好 / >90 优秀
- **诚实边界**：N=7–8，无统计检验，SUS 只作方向性指标；按人四档报，不做加权平均。

### 建议演示的四个数字（照支撑报告 §6.2）

① 任务成功率（n≥5，报百分比 + 四档）；② SUS（若凑得到 5 人以上）；
③ **「到点 → 确认」的端到端耗时**；④ **一次完整闭环里家属端收到「未记录」的延迟**
（演示模式下可测）。

### 支撑报告 §6.3 版本的 60 秒稿（备选，见 demo-script.md §七）

若团队改用支撑报告版本，它的数字锚点是：中国 60 岁以上人群互联网使用率 **53.7%**
（CNNIC 第 57 次，2026-02）；老年人最常用的社交行为是**语音**（微信语音聊天占比
**95.8%**）；以及「长辈模式多数是晚辈代开的」。

## 10. 边界情况与失效模式

| # | 情况 | 处理 |
|---|---|---|
| 1 | 浏览器不支持 `speechSynthesis` | 降级纯视觉 + 大字 + 高对比，不阻塞闭环 |
| 2 | 隐私模式 / `localStorage` 被禁 | 自动切内存态，顶部提示「本次记录不会保存」 |
| 3 | 后台标签页 `setInterval` 被节流 | 载入 + `visibilitychange` + `setInterval` 三处由 `dueAt` 绝对时间重算 |
| 4 | 系统时间被改 / 跨天 | 一律以 `dueAt`（ISO）计算；今日视图按本地日期切 |
| 5 | 断网 | 无 `fetch`、无外链；验收：DevTools Offline + `file://` 双击 |
| 6 | **页面关闭后无法到点提醒** | **如实标注**在 UI 页脚与 README「已知局限」，并作为演示第 4 段「最大风险」明说 |
| 7 | 老人误触、重复点击 | 主按钮二次确认（大号「是，我吃了」/「点错了」）；5 分钟内可撤销 |
| 8 | 老人与家属同一台机器 | 用角色切换，**不假装**多端同步；通知在 UI 标注为**模拟** |
| 9 | 单文件体积膨胀 | 上限 300KB；超限则压缩内联 SVG 与注释 |
| 10 | 三人同改 `index.html` 冲突 | P1 冲突闸门：一阶段内 ≥2 次冲突即改为 `src/` + `tools/build.ps1` |
| 11 | Release 附件中文文件名 | 用引号包裹路径；失败则改 ASCII 名上传 |
| 12 | 一位老人中途拒绝录像 | 尊重拒绝，改纯笔录；同意与撤回口径写进记录表页眉 |
| 13 | 演示时被追问「你怎么知道她吃了」 | **只念 §5.2 那段口播**，不越界；禁用词表打印一页在手边 |

## 11. 风险与假设

### 第 9 问交付稿列出的四大风险（照录，已落实到本计划）

| # | 风险 | 具体缺口 | 对策 |
|---|---|---|---|
| 1 | **「到点」在纯网页里做不到系统级推送**（最大技术缺口） | PWA 的 Web Notifications「页面关闭后不保证到点触发」；唯一作者自述「3 天」做出来的同类项目**恰恰没做出提醒通知**；微信一次性订阅「一次授权=一次下发」——**换成小程序也补不上这一格** | 演示时「到点」做成 Wizard 可控的触发；页面常开；话术明说「这是演示装置，不是系统级推送」；写进诚实页 |
| 2 | 演示时被追问「你怎么知道她吃了」而越界宣称 | 装置日志＝取用代理；本项目连装置都没有，信号只有自述与人证，比装置更弱 | 四状态机 + 禁用词表打印贴电脑旁；被追问只念口播 |
| 3 | **老人端「能不能用」取决于入口与任务数，不取决于做得漂亮** | 中国 60+ 微信/小程序渗透率无可核查数字；「语音 vs 大字号极简」在中国高龄人群无实证对比 | 任务数压到 2 个；单任务限时 5 分钟；全程有人陪测；**把「入口可见性」列为第一验收项**；另招 2–3 位家属 |
| 4 | 三天里真正吃时间的是**非编码**部分，且没有可引用的分母 | **没有任何研究给出「2–4 天原型冲刺」中非编码时间的占比**；最接近的整周调查：编码约占 11%，而「环境搭建」是生产力/满意度回归里**最强负预测因子**；METR RCT 实测**慢 19%**；自报速度偏差 40 个百分点 | Day 1 上午先把「本地跑起来 + 断网可跑」做完再写功能；Day 3 上午只修问题不新增功能；排练 3 遍并计时 |

5. `gh` 已登录 `YuMi-06`；`git` 2.56.0 可用。

## 12. 明确不做（照第 9 问交付稿 §2.2）

  信息，功能上是医学判断（PIPL 第 28/29/30/55 条）
- 多档案家庭管理、PDF 报告导出、订阅与定价
