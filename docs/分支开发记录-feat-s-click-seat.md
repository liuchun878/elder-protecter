## ① v1.9 · 点哪看哪 + 走位真正接上 navgrid

**用户口径**：「根据这些场景制作一个**可以点击的 3D 场景网页**」。
页面（`prototype/suite.html`）本来就在、点击链路也通 —— 这一轮补的是「点击之后**看不看得见**」与
「走过去**像不像话**」这两件"点得动但不成立"的事。

### 改了什么

| 文件 | 改动 |
|---|---|
| `prototype/js/scene3d.js` | 新增 `scene.focusSeat(seat)`：从落座点**正面**往外找机位（正面 → 左右 35°/70°/105°/145°/180°，距离 2.4/3.0/3.6/1.9 m），取第一个同时满足 ①在户型内 ②视线上**不隔墙**（门洞放行）③**不陷在家具里** 的位置；0.85 s easeInOut 平滑飞过去；找不到返回 `null`（保留原机位，**不硬凑**）。新增 `setAutoFrame/isAutoFrame/getFocusPose/isCameraMoving`；用户一拖拽 / 一切机位立刻交还控制权 |
| `prototype/js/person.js` | 走位从**两点一线**改成**沿 `findPath` 折线**（契约 §3.1.1 v1.7 早就这么要求，实现一直没做）：落座点在家具内部 → 终点拆两段「折线走到坐具外入口点 + 最后一段落座收尾」；短于 1.2 m 不走折线；`findPath` 末节点离目标 >0.12 m 时补一段收尾 |
| `prototype/js/scene2d.js` | 补 `focusSeat/getFocusPose/isCameraMoving/setAutoFrame/isAutoFrame` 空实现（2D 俯视本来就把整户画在一屏，不需要"点哪看哪"） |
| `prototype/suite.html` | 打开自动取景 + 新增「取景：跟随点击 / 手动」按钮；操作说明改写 |
| `契约-接口.md` | §3.1 新增 `focusSeat / setAutoFrame / isAutoFrame / getFocusPose / isCameraMoving`；§3.1.1 补「落座点在家具内部怎么办（入口点 + 收尾）」 |

### 关键决策与踩坑

- **取景不是场景缺陷，但看不见就等于没反馈**：`living` 预设的 `lookAt` 是**电视墙**，而沙发被自身扶手 +
  茶几 + 边柜围在凹槽里 —— 点沙发她**真的坐上去了**，可那一格画面里看不见人（只露个头顶）。
- v1.8 试过 18 组候选机位要"补一个对着沙发的预设"，判定不可行后 `cut`。**v1.9 换了思路：不新建预设，
  机位按落座点算** —— 把"机位"从**常量**变成**按点求解**，就绕过了那个凹槽。`S15` 因此从 `cut` 变 `done`。
- 默认**关**（`setAutoFrame(false)`）：主演示 `index.html` 与拍摄模式 `?film=1` 的构图是逐帧复现的基准，
  不能被"点击"这种交互改掉；只有预览台自己打开。
- **实现与契约不一致 = bug**：契约说 `person.js` 沿 `findPath` 走，HEAD 其实是两点一线。
  实测跨房间点卧室 C 床沿**穿墙 2 次**、餐椅/地面穿家具 13–29 帧。

### 验证证据

| 工具 | 结果 |
|---|---|
| `.preview/clicklive.mjs`（**真鼠标事件**，非直接调 API） | 11/11：点沙发/餐椅 → 落座点到状态 → 她走到（0 / 0.02 m）→ 根节点压低进坐姿（−0.29/−0.32）→ 机器人停在她跟前 0.90/0.96 m → **相机切到 `seat` 机位且人被投影到画面内**（NDC (0, −0.31)） |
| `.preview/walkdiag.mjs`（4 落座点 × 500 帧逐帧采样） | 改前穿墙 2 次 → 改后 **穿墙 0 次、中途侵入实体最深 0 m、到点误差 0 m** |
| `.preview/sitfix.mjs` | 8/8（沙发/餐椅/地板/床沿都到点且进坐姿） |

### 顺便纠正的两条**错记录**

1. `STATUS.md` 的「落座缺陷：人到不了坐具、也进不了坐姿」**在 HEAD 上复现不出来** —— 改前实测四种落座
   都到点（0 m）且都进坐姿。那条描述的是**一次已回滚修复尝试的中间态**，被误记成基线缺陷。
2. `.preview/sitfix.mjs` 的旧断言 `rootY > 0.10` **方向写反**（坐姿是把根节点**压低**，站姿才是 ~0.012），
   所以一直报 3 条假失败 → 改为 `rootY < −0.05`（席地另判 `< −0.4`）。
3. 另有：`plan/tasks.yaml`（"机器可读的任务真相"）被改成了**非法 YAML**（双引号标量里塞裸 ASCII 引号），
   `yaml.safe_load` 直接抛 `ParserError` → 已修好并重新通过解析。

## ② v1.10 · 机器人本体换成用户 PR #2 的版本 + 客厅三件坐具转 180°

**用户口径**：「**将机器人替换成这个** `<PR #2>`」、「**把场景中三个沙发旋转 180 度**」。

### ②-a 机器人（契约 v1.10）

**来源**：`liuchun878/elder-protecter` PR #2（分支 `feat/robot-demo`，head `af7def5`
「remove dispenser, tray retracts before doors close」/ `6cc1321`「doors open 90deg」）的
`suite-3d/robot/index.html`。**只借结构、不借资产**：全部用 Lathe / Box / Cylinder / Extrude 重建。

| 件 | 做法（数字来自 PR #2） |
|---|---|
| 蛋形机身 | 一条侧轮廓 `LatheGeometry` 回转成型：高 **0.500 m**、最大半径 **0.190 m** |
| **前下方对开门** | 左右各一扇（`LatheGeometry(轮廓, 22, phiStart, 0.42 rad)`），绕各自**外侧竖边**摆到 **90°**；门扇半径比机身大 5 mm（贴弧面不留缝）；带中缝细线、圆把手、上下铰链活页 |
| 门后暗腔 | 内壁 + 底板 + 舱内导轨 + 隔板 + 药 |
| **带导轨托盘** | 盘面 / 前沿挡边 / 伸缩导轨（尾端 0.26 m 始终留在舱内 → **拉出去不脱节**）；盘上温水杯、铝塑药袋（两排三列）、掀盖药盒、酒精棉、纱布卷 |
| 头部 | 挤出圆角矩形 **0.310×0.170×0.060** + 脖座 + 托座；屏是画布贴图（红/绿眼睛 + 嘴 + 指示条） |
| 底盘（v1.11 补齐） | 左右驱动轮 + 前方两万向轮 + 支架，**随行走滚动** |

**动作时序（写进契约）**：出药「**先开门、后出盘**」；收药「**先收托盘、再关门**」（托盘没进舱门不合）。
判据仍然只有 `state.activeEventId` 一个 —— 只加了两个 0..1 的**视觉**进度。

**⚠️ 与 PR #2 刻意不同的三处（红线，不是漏做）**：

1. PR #2 屏上写着「请取药 / **已服药** · 祝您健康」—— 本项目 **3D 里不渲染任何文字**、界面**不得出现「已服下」**
   （取药 ≠ 服药）→ 屏幕**只画眼睛与指示条**，颜色表示状态（青蓝待命 / 琥珀提示 / 青绿回桩）。
2. PR #2 有「**注水**」水流与「**老人的手**」—— 王阿姨是独立的 `person.js` actor、动作语义固定为「开舱递药」
   → 不引入注水与手。
3. 保留我们的**四轮底盘与车尾充电触点**（PR #2 原本无轮；用户给的参考图里轮子可见）。

**实测**（`.preview/robotnew.mjs` 6/6）：门 **±1.571 rad = 90°**；托盘 `z` **0.030 → 0.230**；收药 3 帧后
托盘已在回程（0.200）而**两扇门仍开着** → 再 30 帧全部归位；收好时外形 **0.389 × 0.682 × 0.400 m**
（＜ 碰撞直径 0.48 → `navgrid` 零影响）；3D 零文字几何体；`robot.update` 仍是纯函数。

### ②-b 沙发转 180°

三人沙发 `rot −π/2 → +π/2`，两个扶手沙发各 `+π`。改前是**背靠背**（沙发背对电视墙、两个单人沙发背对沙发），
改后**围住茶几**、沙发正对电视墙。

**跟着一起改的四处**（家具朝向、座面元数据、路径点、朝向是同一件事的五个副本）：

- `SEAT_SOFA.facing −π/2 → +π/2`，`lockX 2.10 → 2.40`；
- `WAYPOINTS.living_room` x → 2.40；
- `person.js` 预设朝向与初始 `view.facing` → +π/2；
- `main.js` 控制台「坐沙发」按钮的硬编码落座点；
- `APPROACH_POINTS.living_room` 改到**沙发南端外侧 (2.55, 5.05)** —— 转过来后"正前方"紧邻茶几，
  实测沙发占位外扩 0.22 后与茶几只剩**负间隙**，0.5 m 的缝塞不进机器人。

**实测**：`.preview/roomview.mjs` 改前/改后俯瞰 + 正面各一张，并排图 `.preview/shots/room/compare-seatgroup.png`；
原地转（不挪位）→ 家具占位 AABB 几乎不变 → `navtest` 6 条路线仍 0 帧穿墙。

## ③ v1.11 · 夜晚档 + 夜间荧幕 + 大字卡缩小 + 童声督促

**用户四条口径**：① 再增加一个**夜晚**的场景 ② 夜晚机器人**屏幕关闭或转暖光**
③ 左上角**时间确认的屏幕缩小** ④ 到吃药时间机器人**走到奶奶身边督促吃药，声音是童声**
（④ 的来源：他仓库的 `suite-3d/robot/voice/p1..p3.mp3` 与 HEAD 版 `suite-3d/robot/index.html`）。

### ① 夜晚档（S · 契约 v1.11）

| 档 | 太阳 | 半球/补光 | 曝光 | 天空 | 室内暖光 | 环境贴图 IBL |
|---|---|---|---|---|---|---|
| 白天 | 2.35 暖白 | 0.72 / 0.42 | 1.06 | `#d9d6d1` | 关 | 白天天空 |
| 黄昏 | 2.30 低角暖橙 | 0.40 / 0.30 | 1.04 | `#cfc3b4` | ×0.8 | 白天天空 |
| **夜晚** | **0.30 冷月光** | **0.20 / 0.10** | **0.88** | **`#1a2130`** | **×1.75（主光）** | **夜空（新增）** |

**关键一条**：只压阳光与曝光**不够** —— 白墙会被白天的天光（`scene.environment` 的 IBL）整体提亮，
画面会变成"白天关灯"而不是"夜里开灯"。因此 `skyCanvas(seed, mode)` 增加 `'night'`（深蓝夜空 + 月光），
启动时多烘一张 PMREM，切夜晚时**换掉环境贴图**。入口：预览台与主演示的「光照」按钮都改成**三档循环**。

### ② 夜间荧幕（R）

`robot.js` 只读 `sceneApi.getTimeOfDay()`（契约 §3.1 已有该查询，**未新增业务状态**）：
夜晚 + 待命 → 荧幕**熄灭**（`visible=false`），腰线/前条/肩灯统一压 55%；
夜晚 + 递药 → 荧幕亮起走**暖光** `#ffb066`、亮度 ~0.6（白天 0.92–1.0）；白天/黄昏行为一字未改。

### ③ 大字卡缩小（R）

卡片 `min(620px,46vw)` → **`min(500px,34vw)`**（实测 490px）；内边距 `26/30/28` → `18/22/20`；
主文案 44 → **38px**（仍 ≥30dp）；正文 26 → **22px**（硬数值下限）；确认按钮 `220×84` → **`190×72`**
（点击目标仍 ≥60×60）。**只收卡片占位与次要文字，适老化硬数值一条不破。**

### ④ 童声督促（R + 资产）

- **童声通道**（`audio.js`）：照搬他仓库 HEAD 版的做法 —— ① 优先播**预录童声 mp3**
  ② 播不了就 **TTS 抬高音调**（`pitch = 1.70`）兜底 ③ 音色优先级相同（系统童声 > 男声 > 女声 > 任意中文）。
  成人向语音仍**放慢语速**（0.85，适老化）。
- **新场景**（`main.js`，装配层，**不新增业务规则**）：有未确认的提示事件 **且** 机器人**已到达场景给的停靠点**
  （≤0.25 m）时，用童声念「奶奶，药已经放在托盘上了。<医嘱原文>，请取走」；同一轮（事件 + 第几次尝试）只督促一次。
  ⚠️ 判据用「到停靠点」而不是固定距离：预设落位时沙发正面被茶几占住，机器人只能停南侧 ~1.5 m，
  用固定距离会导致跨房间/预设场景**一次都不督促**（自测里抓到的假通过）。
- **三段录音已入库但默认不播**（`prototype/assets/voice/p1..p3.mp3`，来源/时长/sha256 见
  [THIRD-PARTY](../THIRD-PARTY.md) 与 [assets/README](../prototype/assets/README.md)）：

| 文件 | 原话（用户提交说明） | 为什么不默认播 |
|---|---|---|
| `p1` | 吃药提醒 | 里面有「您把这**三粒**药吃下去」——**粒数写死**，而本项目不做剂量计算、演示数据 4 条计划剂量各不相同 |
| `p2` | 鼓励 | 原话「奶奶真棒，**药都吃完啦**」—— **「吃完」= 已服下**，本项目最硬的红线（系统只知道"已取走"） |
| `p3` | 留言已同步子女手机 | 措辞与「记录已同步」一致、可用；单为它破例不值当 |

想听录音本身：网址后加 **`?voiceclip=1`**（只影响演示，不改任何业务）。

## ④ v1.12 · 机器人借 `robot-3d` 的细节（用户选 B）

**用户口径**：「将机器人改进一下，使用这个 `<链接>`」——但给的三个链接都是仓库杂项提交
（`2a89550` = Chrome `GrShaderCache/data_2`；`2b41016` = `111111.00/voice/p3.mp3`；`592d6e0` = `robot-3d/check_glb.py`），
**都不是机器人改动**。真正的机器人在 **`robot-3d/`**：按实拍照片重建的**白色立柜式**送药机器人
（整机 1.112 m、0.314×0.316 近方黑玻璃屏、不锈钢立柱 + 顶部摄像头、木拉手、3 个万向轮、侧推杆）。

**问过之后的决定**：用户选 **B —— 保留蛋形机，只借 robot-3d 的细节**；递药动作**仍是正面出托盘**（机构不动）。

| 借来的 | 做法 |
|---|---|
| 近方大屏比例 | 头 0.310×0.170 → **0.300×0.240**；屏 0.278×0.138（长宽比 2.01）→ **0.268×0.208（1.29）** |
| 屏幕 4 套画面 | **logo** 待命（三条竖杠 + 细横线，即实拍照片那块屏）/ **eyes** 递药中（琥珀）/ **green** 已取走·记录中（青绿 ✓ 圆环 + 满格条）/ **off** 夜晚待命 —— **仍零文字** |
| 木拉手 | 背面两根木色圆棒（Ø0.015×0.190，程序化木纹）+ 四个铝支架 |
| 底盘腰线 / 下缘 | 机身 y=0.085 一圈深灰腰线（与 y=0.315 的青蓝发光带区分） |
| 万向轮结构 | 补**轮轴**与**轮辋**；前万向轮再加**立柱 + 轮架板** |
| 屏幕压条 / 小琥珀块 | 屏下压条 + 屏右上角一颗小琥珀状态灯（有提示事件才亮） |

**刻意没借（红线 / 口径）**：① **顶部摄像头** —— 本项目口径是「不采集摄像头画面、不做识别」，
画面里摆一颗镜头自相矛盾；② **立柜式机身** —— 底盘 0.468×0.428（对角 **0.634 m**），navgrid 现在按
机身半径 **0.22 m** 膨胀，换它必须重算（≈0.32）并重跑连通性，而 v1.8 已查明这套户型很紧
（沙发与茶几之间只剩负间隙）。保留蛋形机 → **碰撞体积零变化**（收好外形 0.389×0.730×0.400 < 直径 0.48）。
