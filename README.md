## 使用说明

- 文件名不区分大小写，`.step` / `.STEP` 为同类文件的不同导出批次。
- 大文件（STEP/SLDASM）体积较大，克隆仓库时请耐心等待；如只需查看几何，建议优先下载 STEP 文件。

## 如何推送到本仓库

国内直连 GitHub 会被重置，**必须走代理**。仓库根目录提供了 `推送脚本.bat`，双击即可（脚本会先检测 `127.0.0.1:7890` 是否有代理在监听）。

如代理端口不同，二选一：

```bat
:: 方式一：改脚本里的 PROXY 变量后双击运行

:: 方式二：手动指定代理推送
git config http.proxy http://127.0.0.1:你的端口
git config https.proxy http://127.0.0.1:你的端口
git push -u origin main
```

> 本节来自 `feat/s-click-seat`（S/H 线的 3D 仿真原型：契约 · 三线分工 · 可点击场景 · 童声督促 · 夜晚档）。

Team4 ｜ Vibe Coding Camp · 立项工作坊

面向**独居且具备独立服药能力**的老年人，把「按时送药 + 取药确认 + 漏服追溯」做成可演示的软件闭环。

| **S** | 场景线 | 房间/相机/光照/性能、演示时钟、装配 `main.js`、集成门禁、录屏 | 想做场景的队员 |
| **H** | 人线 | 王阿姨（3D 人形 + 状态行为）、服药计划、事件状态机、记录、升级链路、家属端、契约 | **队长** |

闭环**按环节**落到三条线（11 个环节全部有主责，不留无主环节），详见 [docs/三线分工与并行开发规范.md](docs/三线分工与并行开发规范.md) 第 1 节。
**合并顺序固定为 H → R → S**，每个里程碑合并一次。

### 队员上手（克隆后 5 分钟）

```bash
git clone https://github.com/liuchun878/elder-protecter.git
cd elder-protecter
```

**按顺序读这 4 份**（顺序不要跳）：

1. [AGENTS.md](AGENTS.md) —— 入口：谁负责什么、能改哪些文件、红线、验证方法
2. [契约-接口.md](契约-接口.md) —— 接口真相：命令签名、数据结构、状态机（**冲突时以它为准**）
3. [plan/tasks.yaml](plan/tasks.yaml) —— 找到你的线、你的块、你的任务 id 与验收标准
4. [STATUS.md](STATUS.md) —— 现在卡在哪、你这一步能不能开工

**每条线的第一步**：

| 线 | 分支名 | 第一个任务 | 第一件要交付的东西 | 自测 |
|---|---|---|---|---|
| **R** | `feat/r-hud-shell` | `R1` | `prototype/index.html` + `css/hud.css`（留 `#scene` / `#hud` 挂载点） | 叠层对比度 ≥4.5:1、点击目标 ≥60×60、100% 缩放不裁切 |
| **S** | `feat/s-scene3d` | `S2` → `S1` | vendored Three.js 两文件 + `scene3d.js` 骨架（含 WebGL 检测与 2D 降级入口） | **断网刷新可加载**、Network 零外部请求 |
| **H** | `feat/h-store-contract` | **`H0`（最高优先，卡住全队）** | `store.js` 命令接口**空实现**（签名对、返回合法默认值） | `store.getState()` 返回含空数组的合法快照 |

> ⚠️ **`H0` 是并行开发的生命线**：R 与 S 都依赖命令接口存在。空实现即可，**不必等业务逻辑写完**。
> ℹ️ **P1 骨架已在分支 `feat/p1-skeleton` 落地**（19 个文件 / 3,766 行，含 vendored Three.js）。
> 也就是说页面能打开了；但**该分支尚未合入 `main`**，克隆 `main` 的队员会看到 `prototype/` 里只有 `AGENTS.md`——
> 此时 `python3 -m http.server` 只会列目录，这是正常的，不是你环境坏了。等 M1 合并后即消失。

**开工前只做三件事**：切到你的分支（`feat/r-…`）、只改你那条线的文件、改完按 [AGENTS.md](AGENTS.md) 第 4 节的 4 项验证跑一遍。

### 本地运行

`prototype/` 通过 ES module 加载本地 vendored Three.js。**`file://` 直接双击会被浏览器 CORS 拦截**，必须用静态服务器：

```bash
cd prototype
python3 -m http.server 8000
# 主屏（3D 场景 + 长者端大字叠层）：http://localhost:8000/
# 副屏（家属端）：                 http://localhost:8000/?view=family
# 交互场景页（保卫老人）：        http://localhost:8000/保卫老人.html
#   （旧链接 suite.html 仍可用：它只是一跳，不是第二份实现）
```

- 户型：**suite-3d 套房**（13.4 × 10.6 m，三卧两卫 + 书房 + L 形餐起居）；机器人与王阿姨都沿**可通行折线**走（`navgrid.js`），不穿墙
- 机器人本体（v1.10）：来自用户 **[PR #2](https://github.com/liuchun878/elder-protecter/pull/2)**（`suite-3d/robot/index.html`）——
  蛋形机身 0.500 m + **前下方对开门（绕外侧竖边开到 90°）** + 门后暗腔 + **带伸缩导轨的药盘**（尾端留在舱内，拉出去不脱节）
  + 圆角矩形头与画布屏（**只有眼睛与指示条，没有任何文字**）+ 四轮底盘。收药时序为「**先收药盘、再关门**」。
  ⚠️ PR #2 屏上的文案（「请取药 / 已服药」）**未采纳**：本项目 3D 里不渲染文字，界面也不得出现「已服下」（取药 ≠ 服药）
- 调试抽屉：页面内按 `` ` `` 或 `Ctrl/Cmd+Shift+D`（**默认隐藏**，观众第一眼看到的必须是产品，不是控制台）
- **室内预览台（v1.7，v1.9 起"点哪看哪"）**：`保卫老人.html` 与主演示**同一份模块**，可自由视角、切机位、看导航网格，专门用来看户型与造型。
  **点画面任意位置 → 王阿姨沿户型通路走过去坐下（不穿墙）→ 机器人感应前往 → 相机自动取景到她**
  （取景是**按落座点算**出来的：在户型内 × 视线上不隔墙 × 不陷在家具里；找不到就保留原机位）。
  不想被自动取景就点面板上的「取景：跟随点击」切成「手动」。
- **点哪坐哪（v1.6）**：在 3D 画面里点任意位置 → 王阿姨走过去坐下（点沙发/餐椅坐坐具、点地板席地而坐）；
  机器人随后"感应"到她的位置并移动过去（右下控制台第二行有机器人视角回显）。
  ⚠️ 这是**模拟位置输入**（点击 / 开关），不是传感器：不采集摄像头画面、不做图像识别。
- **一天里的光（v1.11 三档）**：日光 / 黄昏 / **夜晚**。夜晚天空压暗、**室内暖光成为主光**；
  机器人夜里**待命熄屏、递药转暖光**（`#ffb066`，亮度约六成），腰线/前灯/肩灯统一压暗。接口：`scene.setTimeOfDay('night')`
- **童声督促（v1.11）**：到吃药时间，机器人走到她身边后用**童声**念医嘱原文并说「请取走」；
  再次提醒（第二次/第三次）同样是童声。语音走**预录童声 mp3 → 否则 TTS 抬高音调（pitch 1.70）**两级兜底，
  音色优先选系统里的童声。⚠️ 仓里那三段童声录音**默认不播**（`?voiceclip=1` 才播）——
  其中一段原话是「药都吃完啦」（= 已服下，红线）、另一段写死「三粒」（本项目不做剂量计算）；
  建议的重录文案见 [prototype/assets/README.md](prototype/assets/README.md)
- 演示初始态：演示时钟 `2026-10-03 07:50`、加速 60×（1 分钟 = 1 小时）、王阿姨在客厅、机器人在充电座
- 端口用 8000；**不要占用 19387**（那是本机 DSH 界面的端口）
- 备选：`npx serve -l 8000`

### 离线与隐私

- **离线可用是红线**：无 CDN、无外部模型资产、无网络请求
- 不采集摄像头画面；不向家属推送依从性评分或排名；本地存储优先
- **王阿姨是虚构人物**：仓库、录屏、投屏画面里不得出现任何真实老人的姓名、电话、住址、健康数据
- 不得提交 token / 凭据

### 红线（不可越界）

只做「提醒 + 记录 + 通知」，**不做任何医学判断**：不给补服建议、不做剂量计算、不给药物相互作用结论、不自动呼救、不做医疗用途宣传。完整清单见 [两天开发计划.md](两天开发计划.md) 第 9.1 节。
