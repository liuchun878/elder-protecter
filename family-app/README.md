# 子女端提示 App（family-app）

送药机器人系统的**子女手机端**交互原型。机器人负责「找到人 → 送到手边 → 确认吃下」，
这一端负责**让子女安心**：接住 6 类情景的推送，并能回看**近一周服药记录**。

- 形态：**单文件静态网页**，双击 `index.html` 即开，无需服务器、无需联网、无外部依赖（字体全部回退系统字体）。
- 视觉：莱茵生命（Rhine Lab）风格 —— 深色实验室底 + 青色数据主色 + 琥珀警示 + 切角面板 / 等宽字 / 扫描线。
- 端口：以 414 × 872 的手机壳呈现；窄屏自动全宽。

## 目录结构

| 路径 | 内容 |
| --- | --- |
| `index.html` | 子女端提示 App —— 总览 / 告警 / 用药 / 数据 / 设置 五个 Tab（全部内容内联），唯一交付文件之一 |
| `robot-settings.html` | **机器人基础设置** —— 同一份文件也在仓库根目录 `设定界面app/index.html`（该目录为正式入口，本处保留便于与子女端 App 对照） |

## 五个 Tab

| Tab | 内容 |
| --- | --- |
| **总览** | 老人状态卡（王阿姨 · suite-3d · 客厅沙发）、今日已服 2/3、近 7 日依从 81%、今日排程条、**6 类情景卡** |
| **告警** | 待子女确认的 2 条（标记已处理 / 回拨通话 / 查看详情）+ 今日事件流（全部 / 异常 / 紧急） |
| **用药** | **近一周 7 × 3 网格**（点日期切换）+ 依从率环 + 逐次明细（药名 / 位置 / 判定 / 延迟原因），支持搜索与状态筛选 |
| **数据** | 药品库存（余量不足 1 天 → 提前 24h 提醒）、设备自检、5 路感知模块、**导出近一周记录（复制 / CSV）** |
| **设置** | 六条推送开关、阈值配置、关联设备 |

## 六类情景与推送文案

| # | 情景 | 子女端收到的推送 |
| --- | --- | --- |
| 01 | 常规场景 | 「08:02 王阿姨已按时服药：氨氯地平片 5 mg ✓ ｜ 碳酸钙 D3 片 1 片 ✓」 |
| 02 | 用户处于睡眠状态 | 「12:49 已服午药（**延迟 19 分钟**）」+ 原因条「等待起床」 |
| 03 | 卫生间 / 厨房 / 阳台 | 「在卫生间门口取药并服下（机器人未进入私人区域）」 |
| 04 | 疑似跌倒 / 身体不适 | 「⚠ 21:14 检测到可能跌倒，已自行站起，自述『有点疼』」 |
| 05 | 服药后发现不适 | 「⚠ 19:02 服药后自述不适」+「已附上近一周用药记录 21 条」 |
| 06 | 机器人无法正常送达 | 「设备故障 · 任务降级（2 次脱困失败）」+ 卡困位置 |

### 交互路径

1. 点任意**情景卡** → 抽屉打开：情景概述 → 触发判据 → 三级唤醒 / 行为链路 → 准入规则 →
   机器人侧行为闭环 → **手机上实际收到的推送**（带「原因」条）→ 数据面板 → 设计意图。
   点「复现此推送」会在手机顶部播一次横幅动效。
2. 右上角 **◎ 图标** → 依次下发 6 条演示推送；**⚠ 图标** → 防跌倒 / 服药后不适的**全屏强制弹窗**
   （一键回拨 / 接通机器人扬声器 / 通知社区）。
3. 「用药」页点周六或周日的日期块 → 可见晚间那条**未服**记录，原因注明由设备卡困导致，非老人漏服。

## 与既有设定的对齐

阈值与文案取自仓库外的项目文档《机器人行为设定》《具体情景分析》《场景 Storyboard》：

| 参数 | 值 |
| --- | --- |
| 提醒间隔 / 未取走超时 | 2 min / 10 min（收回药片与水，药片直接报废） |
| 停靠距离 | 厨房门外 600 mm ｜ 卫生间门外 800 mm ｜ 阳台门口不驶入 |
| 与人距离 / 停稳 / 水杯 | 200 mm（机体运动闭环） / 2 s / 60% |
| 取药判定 | 药片消失 + 杯子放回，**只靠摄像头**；私密区不做验证 |
| 升级原则 | 双条件触发（算法判定 + 老人确认），延迟必须带原因 |

隐私边界：**只推状态、不推画面**，摄像头画面不上传云端；机器人不是医疗器械，不提供诊断、不建议加药或停药。

## 机器人基础设置（设定界面app / robot-settings.html）

子女端给送药机器人做**基础设置**的界面：把「该送什么、什么时候送、能看什么」下发到机器人，
机器人据此生成**本地排程**并出药。共 5 组设置，都在同一个 414 × 872 手机壳内，底部有「下发到机器人」保存条。

> 正式入口为仓库根目录的 **`设定界面app/index.html`**（`设定界面app/README.md` 有完整说明）；
> 本目录下的 `robot-settings.html` 是同一份文件的副本，保留以便与子女端 App 对照。

| 设置组 | 内容 |
| --- | --- |
| **用药计划** | 录入项与《机器人行为设定》§四一致：**名称 / 剂量 / 频次 / 有效期 / 与进餐关系**；频次拆为「每日 N 次 + 具体时段」，可增删时段、按需用药；另提供「粘贴医嘱快速录入」把一行医嘱解析成结构化字段（草稿，需进编辑核对） |
| **余量与有效期提醒** | **余量不足 1 天 → 提前 24 小时提醒**（并给出计算式：余量 ÷（单次剂量 × 每日次数）= 剩余可用天数）；**过期药品 → 提醒更换**；60 天内到期为提示级；可「标记已补药 / 标记已更换 / 调整用量」，处理后时间与原因留痕 |
| **装药核对** | 逐格引导核对（防错）：核对通过前该格不出药；余量为 0 标记需补药；含废弃药片仓容量与清理留痕 |
| **隐私设置** | 是否**启用摄像头**（关闭即无法确认是否服下，只能记「已送达 / 未取走」）；**是否需要每一次用药都播报**；播报是否含剂量与进餐关系；私密区域改用语音提醒。不可关闭项单列：画面上云=否、私域不启用摄像头、只拍手部区域 |
| **提醒与对话参数** | 提醒间隔 2 min、未取走超时 10 min（收回药片直接报废 + 上报）、分时段音量、三级唤醒次数与间隔 |

演示数据（虚构）：苯磺酸氨氯地平片 5 mg 每日 1 次早餐后 ；
阿托伐他汀钙片 20 mg 每日 1 次晚餐后（有效期 2026-12 → 提示「临近」）；
碳酸钙 D3 片 每日 2 次早晚餐后（余 2 片 ÷ 2 片/日 = **1.0 天** → 触发「提前 24 小时」，
且有效期 2026-08 **已过期** → 触发「提醒更换」）。

> 频率、余量与有效期的计算全部由页面内数据实时推导；改剂量或频次后，
> 首页「今日排程预览」与提醒中心立即重算。

## 推送到 GitHub

国内直连 GitHub 会被重置，需走本地代理。仓库根目录提供了 `推送脚本.bat`（默认检测 `127.0.0.1:7890`）。

```bat
git add family-app
git commit -m "add family-app: 子女端提示 App + 机器人基础设置（用药计划 / 余量与有效期提醒 / 隐私设置）"
git push origin main
```

> 演示数据声明：王阿姨是虚构人物；界面展示的均为事件状态与脱敏数值。
